# KingdomComeGlueMapper Setup 0.3.28

This Windows x64 prerelease brings the NPC appearance, gameplay conversion,
lighting, cache and resume improvements made since the last published release,
**v0.3.16**. It uses gameplay recipe **61** and appearance policy **2**.
The changelog covers 62 commits through `cae0d3e`, plus the release documentation
update. These fixes are part of the normal Setup builders and supported saved
package upgrades.

## Download and upgrade

- Download **KingdomComeGlueMapper-Setup-0.3.28-win64.exe** from this release's
  Assets. Python is bundled; Microsoft Edge WebView2 is required.
- KCD1 Map requires local KCD1 and KCD2 installations and the official KCD2
  Modding Tools. Game archives and the Modding Tools are not redistributed.
- To continue a saved build, close the older Setup and use **Activity → Restore /
  upgrade build…** in this version. Select the original folder containing
  `job.json`. Supported receipts from recipes 3–61 are checked before migration
  or reuse; successful validation is still required. Keep the original workspace.
- Matching completed map work, bake checkpoints and cache entries can be reused.
  Resume accounts for remaining work when checking build space. Incomplete map
  conversion can still require restarting that phase.
- The source clothing repair is integrated into Setup, including saved appearance
  upgrades; a separate test repair is not required. Mixed appearance archives
  retain their carried equipment instead of failing the ownership check.
- Use **Launch mod** from Setup for the map's prepared runtime and shaders.

See the [Windows setup guide](https://github.com/SamG-Coder/KingdomComeGlueMapper/blob/v0.3.28/docs/windows-setup.md)
for installation requirements, space allowances and cache behavior.

## Changes since v0.3.16

### NPC appearance and clothing

- Reworked source clothing conversion around native equipment layers, region
  selection, authored fitting and outfit composition. Preserve female garment
  bodies and source body geometry where fitting is inappropriate.
- Restore armour-linked clothing details such as belts, sleeves, bands and
  straps; retain NPC equipment presets when upgrading appearances.
- Repair body/head visibility and neck coverage rules used by converted outfits.
  Apply the conversion and validation consistently to authored LODs.
- Cap float clothing textures at 2048 so their streamed pieces stay within
  retail limits, while preserving the required material and texture families.
- Convert missing loot clothing dependencies through the shared importer.
- Add a developer clothing/body workbench and outfit audits to inspect source
  conversion, native region selection, clipping and coverage failures.

### Build speed and progress

- Bake NPC outfit textures in worker processes and reuse the asset library index.
  Validate human asset caches against the index that produced them, and stage
  wearable conversion beside the cache to avoid an extra copy.
- Share source table/archive lookups across a fresh NPC batch. Reuse macro bakes
  by their actual inputs and blood/grime masks by their source and channel policy.
- Package final component dependencies, excluding unused intermediate outputs
  while retaining mesh LODs, streaming texture families and carried equipment.
- Reduce repeated skin validation work and accelerate body-coverage candidate
  selection without changing the final intersection/alpha checks.
- Report character counts, body/clothing parts, packaging work and measured
  progress instead of leaving a long NPC operation at an uninformative 0%.
- Run native shader compilation alongside world conversion. Bake lighting tiles
  in parallel with bounded memory for dense CPU/GPU work; cancellation stops new
  tiles and joins active work before reporting failure.
- Correct surface-placement progress callbacks and saved-job string path handling.

### Lighting, cache, resume and installation

- Restore native exposure after a surface bake, including supported older saved
  packages, and keep the converted level-wide probe out of volumetric fog.
- Discover existing lighting caches in the selected workspace without requiring
  selection of their originating job. New cache metadata describes the static
  scene and the materials it uses, avoiding invalidation by unrelated NPC assets.
- Validate cached output hashes and tile layouts. Legacy caches without recorded
  scene inputs are explicitly reported as such; their input compatibility is not
  claimed as verified. Ambiguous candidates are rebuilt.
- Preserve compatible completed bake checkpoints while checking gameplay
  upgrades, and calculate remaining resume space from retained work.
- Repair supported stale LOD sections using verified saved build evidence.
- Reuse verified installed files during transactional staging and preserve the
  single playable world when refreshing gameplay and appearances.

### World and NPC interactions

- Apply KCD2 octree placement rules to converted roads, decals and water in fresh
  and cached map packages.
- Convert supported authored designer collision and barrier volumes, with
  follow-up collision repairs and source-linked gate access fixes.
- Restore market stalls and repair shop, training and other gameplay handoffs.
  Converted shopkeepers receive native haggling and shop-ending roles.
- Extend source-linked work conversion for shop guards, seated embroidery,
  town benches, fence repair, wood chopping, household water and home rest.
- Add NPC sleep schedules, bed selection and family bed assignments; restore
  forge-loft furniture and hay placement.
- Add the starting torch, trainer invitation/departure adapters, sword-training
  handoff and initialization fixes, ambient work speech and native road encounters.

### Quest and developer tools

- Add a separate **Quest & NPC Tests** logic emulator with deterministic timers,
  messages, dialogue branches, object queries, collections, snapshots and reports
  in HTML, JSON and JUnit formats.
- Audit converted quest graphs and dependencies, and apply generic importer fixes
  for objective callbacks, linked conditions and source/runtime identity handling.
  Unsupported operations and missing inputs remain visible failures.
- Add isolated SDK testing and document runtime MCP acceptance and public-client
  capability limits.
- Share chunk-digest and inline entity-link helpers across tools, retaining the
  hexadecimal geometry-signature format expected by existing callers.
- Refresh project documentation, screenshots and project/social links.

The emulator and clothing workbench are **developer source tools**, not new Setup
screens. The emulator tests declared logic contracts; it does not render the world
or reproduce the complete KCD2 engine.

## Measured performance and validation

- **2,241 automated tests run, 17 skipped, no failures** on the release's runtime
  source (`cae0d3e`). The subsequent release changes are documentation only.
- The packaged **0.3.28** executable passes its frozen self-test: 109 converter
  modules, local web UI/runtime resources, worker pools, a 331-character staging
  path and the OptiX/reference byte-equivalence sample.
- Six fresh appearances took **89.2 s before → 63.2 s after** the first performance
  changes, about **29% less conversion/packing time**. This measured improvement
  predates the additional effect-mask deduplication in this release.
- Effect-mask sharing removes **149.36 MiB** from Father's generated package.
  A six-actor comparison preserves all **77 skin/LOD payloads**, retained
  nonmaterial assets and resolved material surfaces.
- A fresh **61-person** run before that final mask-sharing change measured
  **361.29 s conversion + 102.57 s packing**. These are appearance-only timings,
  not a full Setup, map, lighting or installation estimate.
- Contributor measurements in
  [PR #45](https://github.com/SamG-Coder/KingdomComeGlueMapper/pull/45) report a
  1,220-tile Buildings bake in **23.5 minutes** on a 24-thread machine with
  64 GB RAM and an RTX 5090 32 GB, with tile hashes matching serial output.
  This is a historical measurement of that configuration, not a benchmark of
  every v0.3.28 recipe or the All (Forest) preset.

See the [appearance investigation](https://github.com/SamG-Coder/KingdomComeGlueMapper/blob/v0.3.28/docs/clothing-native-rendering.md)
and [quest validation record](https://github.com/SamG-Coder/KingdomComeGlueMapper/blob/v0.3.28/docs/quest-emulator-validation.md)
for evidence and limitations. Appearance generation still duplicates substantial
texture data between NPC packages; batch-wide shared immutable assets remain
future work. This release does not claim that clothing build time is fully solved.

This remains experimental. The package self-test and converter checks do not
establish a complete retail campaign, all-outfit visual correctness, every fence
or barrier interaction, or save/load compatibility. Full campaign conversion,
KCD1 save migration and two-client multiplayer gameplay remain unfinished or
unverified within the documented acceptance boundaries. The bundled GPU payload
targets `sm_120`; unsupported hardware uses the CPU fallback.
