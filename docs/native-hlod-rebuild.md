# Native HLOD rebuild: implementation and validation boundary

The distance-only runtime experiment is not a replacement for HLOD. Disabling
the system also prevents detailed scene placements from loading. The previous
bounds-only rebuild retains old proxy memberships and did not fix the reported
synchronized tree changes.

## Implemented stages

`tools/native_hlod_scene.py` reads the final converted placement records and
resource tables. It excludes old proxy records, discards old group membership,
and constructs an editable KCD2 scene. Each brush instance receives a distinct,
deterministic identity, including repeated instances of the same model. Signed
scale, rotation and position are preserved; nonrepresentable shear is rejected.
Vegetation is written as native Version 3 instances, not substituted brushes.
Editor elevation is reconstructed from the converted terrain for the correct
world extent and vegetation alignment. Original gameplay and merged vegetation
packages are not rewritten.

`tools/editor_archive.py` implements the bounded CXmlArchive/CNamedData format,
including compressed blocks, duplicate/length validation, and unsupported-flag
rejection. Layout references are the CryEngine-derived serializers:

- https://github.com/aws/lumberyard/blob/master/dev/Code/Sandbox/Editor/Util/NamedData.cpp
- https://github.com/aws/lumberyard/blob/master/dev/Code/Sandbox/Editor/Util/XmlArchive.cpp
- https://github.com/aws/lumberyard/blob/master/dev/Code/Sandbox/Editor/VegetationMap.cpp
- https://github.com/aws/lumberyard/blob/master/dev/Code/Sandbox/Editor/Terrain/Heightmap.cpp

`tools/native_hlod_export.py` calls the installed KCD2 editor's native
`-exportHLodTree` command. It checks fresh output and brush identities, geometry
bindings and positions. Proxy references are checked separately from hierarchy
export; an XML reference is not a generated mesh.

## Local validation on 2026-10-19

A two-instance vegetation fixture was accepted by Editor.exe and generated
separate native spatial branches. The full converted world then exported:

- 167,188 brush instances, all identity/model/position checks passing.
- 1,483,225 vegetation instances supplied to the editor; per-instance compiled
  output roundtrip is still required before declaring vegetation parity.
- 4,102 old proxy records excluded from inputs.
- 1,059 ClusterLod and 4,361 VegetationLod nodes generated by KCD2.
- 5,419 proxy geometry paths referenced but **not generated**.

The input/output editor scene is approximately 264 MiB on D:, not a duplicated
game build. Evidence is in `outputs/new-game-compare/native-hlod-world`.
The scene is `KCD2Mod/Data/Levels/gm_native_hlod_world` and is explicitly not an
installable replacement level. Nine native-input/export unit tests pass.

## Remaining implementation

This is not a completed rendering repair and must not be promoted into setup.
The official HLOD RC jobs found in this installation package existing CGFs;
they do not produce the missing cluster geometry. A geometry/material/texture
baker is still required, followed by compiled native export and retail testing.
Native vegetation render settings also require roundtrip parity checks.

The native export log reports zero mean face area for four existing converted
models (`setup_buildings/mesh617`, `setup_buildings/mesh67`,
`setup_props/mesh2058`, `setup_props/mesh2169`) and empty bounding boxes for some
placements. These need classification/repair before a production bake. They do
not by themselves establish the cause of the synchronized tree LOD bug.

No installed mod archive, runtime LOD configuration, or setup recipe was changed
by this native rebuild implementation. The existing bounds-only experiment is
still the installed version until a complete replacement is validated.

## Proxy baker proof, 2026-10-19

`tools/hlod_proxy_mesh.py` and `tools/bake_native_hlod_proxy.py` now implement
bounded leaf-cluster geometry composition. They preserve vertex streams and
texture references, build one combined material, remap each subset's material
index, and express every instance relative to its native cluster origin.
They do not require RC to recompile already-compiled CGFs. KCD2 Editor.exe
accepted a real 16-placement cluster (17,067 triangles, 19 submaterials,
528,136 bytes) and a 279-placement vegetation cell. Evidence is under
`outputs/new-game-compare/native-textured-proxy` and `native-vegetation-proxy`.

The vegetation cell contains 277,335 triangles at full detail. Selecting its
available external mesh LODs up to LOD3 reduces this to 41,394 triangles and
2,529,120 bytes, without deleting instances. This is per-model LOD reuse, not
cross-object simplification or atlasing.

A critical composition rule came from CryEngine's `CStatObj::LoadCGF`: a simple
static object consumes its mesh directly; its authoring node transform is not
an additional runtime placement. External tree LODs in the converted package
contain authoring offsets of tens to over one hundred metres. Applying these
transforms during composition produced an invalid roughly 200-metre envelope
for a 64-metre cell. Following the simple-object rule restores the expected
approximately 68-by-63-metre geometry envelope. This fixes the new baker's
interpretation; it is not evidence that retail applies those offsets or that
the original synchronized LOD bug has been resolved.

Reference:
https://github.com/aws/lumberyard/blob/master/dev/Code/CryEngine/Cry3DEngine/StatObjLoad.cpp

Four new regression tests cover independent placement, material/texture
remapping, missing dependencies, and ignored simple-mesh authoring transforms.
Production work still includes native compiled HLOD switching verification,
coarser parent proxies, single-render-node vertex baking, dependency parity and
whole-world performance/storage bounds. The single-render-node case currently
fails explicitly because native simple-mesh loading would discard a composed
node transform. Neither the whole-world bake nor retail validation is complete
at that earlier proof stage.

## Whole-world implementation

The new resumable pipeline is `bake_native_hlod_world.py`,
`compile_native_hlod_world.py`, `package_native_hlod_world.py`, then
`install_native_hlod_world.py`. These are experimental test-build tools, not yet
a validated setup default. Each stage rejects incomplete upstream output.

The complete first composition pass produced all 5,419 proxy files. A native
large-parent load test then found two real limits that the small proofs missed:

- The native CGF loader rejects a combined table above 128 submaterials.
- Tens of thousands of separate compound subobjects exhausted editor memory.

`merge_hlod_geometry.py` addresses the latter by baking instance transforms into
bounded geometry batches, retaining per-material bindings, UV0/UV1, colours,
tangents and mirrored winding. It recalculates face-area metadata in the baked
space. This does not atlas textures or claim additional mesh simplification.
Available external model LODs are selected only if their material slots match
the placed material; incompatible reduced models fall back to a compatible LOD.
Physics/helper-only source assets remain in the detailed world and are explicitly
reported as having no render surface to add to a proxy.

The `Main_5` parent test retained 36,733 placements (including reported
non-rendering helpers), reduced 36,780 render components to 1,655 batches, and
completed native editor export with 4,726 MB reported peak memory. Its geometry
is 842,469,412 bytes and contains 16,518,306 triangles. This establishes loader
acceptance, not a rendered performance claim. Evidence:
`outputs/new-game-compare/native-hlod-world/merged-parent-export.log`.

Packaging takes native compiled parent-proxy records, topology and hash, remaps
their resource indices, and preserves every existing detailed placement. It
changes only the HLOD entries and appended terrain resource tables. Install
uses bounded rollback entries and hard-linked resource shards on D:, rather
than copying or backing up the entire mod. The installed game must be closed.
